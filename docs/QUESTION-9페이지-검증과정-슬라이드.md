## 1. 이 발표의 논지

**"규칙 기반 검사기를 통째로 유지하는 운영 방식은 실패했지만, 그 부품 일부는 LLM 체제에서 오히려 더 필요하다."**

- 검사기 자랑이 아니다. **무엇을 LLM 체제로 가져갈 것인가**를 정하는 자리다.
- 과장하지 않는다 — 미실행·미완성은 그대로 적는다(8/5 방식의 수치도 "자체 보고"로 격하했고, 우리 것도 "아직 만들지 않았다"고 적는다).

## 3. 질문 대상 슬라이드(9페이지)의 현재 내용

제목: **커스텀 하나(BANK-OM ID)가 검증되는 과정**
리드: *"제안 — 하이브리드에서 LLM 작업의 '증거 층'으로 이 검사기를 도입한다(자랑이 아니라 도입 대상). 커스텀 하나가 아래 6단계로 등록·검사·증거화된다."*

1. **등록** — Manifest·Registry·Contract. 무엇을·어디를 바꿨고 어떤 검사로 지킬지 선언
2. **커밋·변경범위 검사** — 선언한 범위만 건드렸는지, 공식 계보 위에 얹혔는지
3. **공용 파일의 ID별 코드 검사** — 공유 파일에서 이 ID 몫의 코드가 살아있는지
4. **전용 검사 실행** — 이 기능만의 검사(API/화면/소스). 속 빈 테스트면 걸러낸다
5. **commit·이미지와 결과 결속** — 바꿔치기·사후수정을 감지
6. **승인·증거 보관** — 권한자 승인 + 증거 보관. 승인은 결과에 결속

마무리 콜아웃: *"6페이지 한계와의 연결 — '관리 파일이 많다'는 부담을 그대로 두지 않는다. 이 산출물을 사람이 아니라 LLM이 생성·갱신하고, 검사기는 검증만 한다."*

## 4. 실제 질문

**8페이지에서 "전략을 하네스 형식으로 바꾼다"고 선언한 직후에 이 6단계가 나온다. 이걸 여기 둔 이유가 설명되지 않는다.**

구체적으로 걸리는 점:

1. **7페이지(강점)에는 이 6단계가 들어 있지 않다.** 강점은 허위 테스트 방지·막고 보기·못박기·기계 대조·결정론 다섯이고, 6단계는 별개다. 그런데 9페이지는 "이걸 도입하자"고 한다 — **강점으로 제시된 적이 없는 것을 도입 대상으로 내미는 셈**이다.
2. 그렇다면 **이 6단계를 7페이지 강점에 편입해야 하나?** 편입한다면 **무엇을 근거로 강점이라고 설득할 것인가?**
3. 아니면 **9페이지를 지우고**, 10~12페이지(관리 파일 18종)에서 설득해야 하나? **그 경우 설득은 어떻게 하나?** 관리 파일 목록만으로는 "이게 하나의 절차로 돈다"는 그림이 안 보일 수 있다.
4. 혹은 이 슬라이드의 역할이 **설득이 아니라 '사람에게 전체 그림을 보여주는 정보 제공'** 인가? 그렇다면 그렇게 명시해야 하는가?

## 5. 제약

- **장수를 늘리지 말 것.** 지금도 본문 15장이다. 통합·삭제는 되지만 신설은 피한다.
- **중복 설명을 늘리지 말 것.** 이미 같은 말을 여러 장에서 반복한다는 지적을 받아 세 장을 삭제한 이력이 있다.
- **과장 금지.** 6단계 중 실제로 전부 돌려본 것은 일부다(런타임 계약 일부 미실행, 승인·증거 보관은 설계 단계). 강점으로 편입한다면 **어디까지 실행으로 증명됐는지 구분**해야 한다.
- 답변은 **결론 → 근거 → 실제 슬라이드 문구(한국어)** 순으로. 문구는 그대로 덱에 넣을 수 있는 수준으로.
