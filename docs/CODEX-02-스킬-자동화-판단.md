# [Codex 평가 요청] 예행연습 자동화 — "확인 로그 + 스킬화" 판단

> 배경: 예행연습 가이드에는 실행 의미보다 **내부 정합성 확인용 조회(파일 수·SHA 등)** 명령이 많다. 운영자는 "오류만 아니면" 각 줄을 눈으로 볼 필요 없이 `100/100 정상 반영` 같은 **요약 로그**만 보면 된다는 아이디어. 사람 판단이 아닌 것 + **검사기 직전 파일 준비**를 **skill**로 만들어 호출하고 싶다.
> 요청: **적대적·비판적·보수적** 판단. 반례가 나올지, 어떤 로그·어떤 스킬이 필요할지, 더 나은 대안이 있는지.
> 형식: **요구사항 : 답변**. Codex는 반례/누락/과신을 지적해 주세요.
> 운영 목표: **안정적 운영** + 손작업 제거(리더들도 동의).

---

## 요구사항 1
실행과 무관한 조회(파일 수·SHA)는 오류만 아니면 되고, 실행할 때마다 `100/100 정상 반영` 요약 로그만 확인해도 되지 않나?

### 답변
**맞다. 녹색 체크를 사람이 일일이 눈으로 보는 건 낭비다(=CI/요약로그 사고). 단, 조건이 하나 있다: 요약의 분모·분자가 "독립 오라클"에서 나와야 한다.**

- 옳은 이유: 결정론적 검증(SHA 일치, 경로 113개, ancestry)은 사람 판단이 아니라 pass/fail이다. 요약 한 줄로 갈음 가능.
- 필수 조건: **오라클(=정답 기준)이 스킬 바깥의 정본이어야 한다.** "100/100"의 100을 스킬이 스스로 만들면(자기참조) 커스텀이 빠져도 항상 100/100이 되어 **거짓 초록**이 된다. → 분모는 `manifest union`·`source-diff-paths.txt@sha` 같은 독립 정본에서.

## 요구사항 2
사람 판단이 아닌 것 + 검사기 직전 "파일 준비"를 skill로 만들어 호출해서 쓰고 싶다. 어떤가?

### 답변
**부분 찬성 + 강한 조건부. 작업을 2가지가 아니라 3가지로 나눠야 하고, 위험은 "준비(상태 변경)"에 몰려 있다.**

| 분류 | 예 | 자동화 | 위험 |
|---|---|---|---|
| (a) 결정론적 조회·검증 | SHA·파일수·ancestry | ✅ 요약로그 | 낮음 |
| (b) **검사기 직전 준비(상태 변경)** | carry-forward 복사, per-ID 커밋 재구성, registry 생성, 마이그레이션 폴더 이동 | ⚠️ 조건부 | **높음(반례 진원지)** |
| (c) 사람 판단 | 113파일→ID 분류, 업무 충돌, 승인 | ❌ 유지 | — |

(b)의 위험: **"성공했다는데 사실 틀린" 준비.** 준비 스킬이 다운스트림 게이트가 통과하도록 상태를 손보면 **정당한 BLOCK을 가짜 PASS로 전환**한다. → 준비는 **결정론·멱등·가역·비의미** 작업만. 준비 후 반드시 **독립 사후검사(기존 검사기 호출)**.

## 요구사항 3
어떤 확인 로그들이 있어야 하나?

### 답변
**모든 초록은 자기 오라클을 이름으로 대야 한다. 하네스의 4-verdict를 재사용하고, 스킬은 verdict를 relay만 한다.**

로그 스키마(스텝별):
```
step: attach-verify
oracle: source-diff-paths.txt@2c23470 (independent)   # 무엇과 비교했나
expected: changed_paths=113, ancestry=0
actual:   changed_paths=113, ancestry=0
verdict: PASS         # PASS/BLOCK/APPROVAL/ANALYSIS_ERROR (새 verdict 금지)
digest: sha256:...    # 하네스 result_io의 tamper-evident 서명 relay
```
롤업: `111/111 반영 (기준: manifest union 111 + excluded 2 = source-diff-paths@sha; upstream afcb2d2)` — **분모 출처 명시.**
- 기계판독(JSON)+사람요약 2벌. 미상/부분/skip = **FAIL(fail-closed)**, 조용한 초록 금지.
- 분자뿐 아니라 **분모(기대 N)도 assert**(누락으로 분모가 줄어드는 거짓말 방지).

## 요구사항 4
단계별로 어떤 스킬들이 있어야 하나?

### 답변
**(a)+(b)만 스킬로, (c)는 수동 유지. 각 스킬은 "기존 러너 호출 + 요약 relay"이지 검증 재구현이 아니다.**

| 스킬 | 감싸는 것 | 유형 | 반례 방어 |
|---|---|---|---|
| `om-preflight` | env·ref 검증 | read-only | 기대상수↔로그 대조 |
| `om-attach-verify` | 브랜치 연결+6 assert | read-only | 분모=source-diff-paths@sha |
| `om-reconstruct` | per-ID 커밋 재구성 | **mutating** | 재구성 후 독립 survival 검사기 호출, per-ID 타이핑 승인 유지 |
| `om-carry-forward` | 등록 1.13.1→1.13.2 이월 | mutating | 파일목록 manifest에서 생성, 이월 후 registry closed-graph 검증 |
| `om-checks` | 검사 배터리 | orchestrate | 기존 러너 호출만, verdict relay |
| `om-evidence-collect` | run_id/digest 수집 | append-only | GitHub API 수집, 손편집 금지 |

(c) 사람 게이트는 스킬로 감싸도 **멈추고 타이핑 승인 요구**, 자동 진행 금지.

## 요구사항 5
스킬을 작은 솔루션처럼 썼을 때 반례가 나오진 않을지? (적대적으로)

### 답변
**나온다. 아래 8가지가 "초록불인데 현실은 깨진" 케이스다. 이 방어를 넣지 않으면 스킬화는 위험하다.**

1. **자기참조 오라클** — 스킬이 분모를 스스로 만들어 검사 → 누락돼도 100/100. → 독립 정본 대조.
2. **검사기 재구현** — 스킬이 `vendor_rebuild`와 다른 로직으로 재구현 → 두 결과 불일치. → 재구현 금지, 러너 호출.
3. **준비 스킬이 게이트 무력화** — 충돌 자동해소/폴더 자동이동으로 BLOCK→가짜 PASS. → 준비는 비의미 작업만.
4. **부분 성공/비원자성** — 100개 중 3개 실패인데 마지막 스텝만 보고 성공. → 원자성+분자/분모 동시 assert.
5. **환경 비결정성** — 로컬 macOS Bash 3.2 vs CI 상이. (실화: `test_upgrade_rehearsal`이 이 회귀를 pin.) → 로컬=CI 동일 코드경로.
6. **스테일 입력** — 어제 fetch·움직이는 `main`에 초록. → SHA pin 우회 금지.
7. **권한 스코프 크립** — (실화) registry `unregistered_findings`가 `.claude/settings.json`의 "자동 승인 훅+광범위 Bash/Edit/Write/MCP 권한"을 **severity:critical, disposition:block**으로 이미 잡음. **자동승인·광범위 쓰기 스킬 = 하네스가 막아야 할 대상 그 자체.**
8. **누락에 의한 거짓말** — 분모가 조용히 줄어듦. → 기대 N도 assert.

## 요구사항 6
더 나은 대안이 있나?

### 답변
**있다(권고). "skill"의 정의부터 갈린다.**

- ❌ **skill = LLM이 skill.md 읽고 알아서 실행/판단** → 비결정론 → 은행 재현성·감사 실패(AI-reapply와 같은 병).
- ✅ **skill = 이름 붙은·버전 관리되는·결정론적 스크립트/Make 타깃을 호출** → 좋음.

**권고 대안:**
> 실체는 **결정론적 CLI/Make 타깃**으로 만들고 **그게 CI와 같은 코드경로**가 되게 하라. **스킬은 그 위의 얇은 손잡이(호출+요약)일 뿐.**

- `make rehearse.preflight`, `rehearse checks --version 1.13.2`, `rehearse reconstruct` … = 실체(product), 스킬 = 문손잡이(doorknob).
- 이점: 재현성·감사(=스크립트), 드리프트 없음(=구현 하나), "호출→요약만 읽기" UX, **로컬=CI**로 macOS↔CI 괴리 제거.
- 스킬은 **검증 로직을 담지 말고** 이 타깃 호출 + verdict relay만.

## 스킬 헌장 (보수적 가드레일)
1. 스킬은 **verdict를 결정하지 않는다**(하네스 verdict relay).
2. 스킬은 **검증을 재구현하지 않는다**(기존 러너 호출).
3. 준비 스킬은 **결정론·멱등·가역**만. 의미판단(충돌/분류)은 **멈춤**.
4. 로그는 **독립 오라클 + 기대 분모 + SHA pin** 명시.
5. **Fail-closed**: 미상/부분/skip = FAIL.
6. **광범위 쓰기·자동승인 권한 금지**(`.claude/settings.json` critical 사례).
7. **로컬=CI 동일 코드경로.**
8. read-only(검증) vs mutating(준비) 스킬 분리, mutating은 **diff 출력 + 독립 사후검사**.

## 한 줄 결론
자동화·요약로그는 옳다. 단 **스킬 = 결정론 도구의 얇은 호출 껍데기 + 요약기**로만. **오라클·검증·의미판단은 스킬 밖(정본/기존 검사기)에** 둬야 "안정 운영 + 손작업 제거"를 감사 가능하게 둘 다 얻는다.
